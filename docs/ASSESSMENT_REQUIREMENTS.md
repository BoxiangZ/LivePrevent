# Assessment 综合评估需求分析

**状态：** Assessment 优化的目标需求；样例工作区已实现主要流程，部分验证与生产能力仍待完成  
**日期：** 2026-10-03  
**适用范围：** 家属端单次 Assessment，基于用户提交的样例资料和系统已有的个人历史基线

## 1. 目标与用户任务

用户提交手动观察、CSV/JSON 资料、补充文字，并可附上一段视频后，应收到一份**基于本次资料所覆盖时间的老人身体与活动状态风险评估**。结果需要回答：发现了什么、哪些证据支持或反驳这些发现、与该人的历史状态有何差异、目前能判断到什么程度、接下来该做什么，以及是否产生预警。

系统应同时检查所有受支持的健康与安全风险，不要求用户事先猜中风险类别。具体可识别的风险类型随经过验证的证据类型和决策策略扩展；本文不将全量评估限制为目前下拉框中的六个场景，也不预设未经验证的医学阈值或概率。资料不足以说明老人的**整体健康状况**时，结果必须明确这是局部、限时的评估。

本文以 [PRD-v1.md](PRD-v1.md) 的辅助照护、非疾病诊断定位和版本化决策原则为前提。它描述目标行为；当前已经实现的接口和字段仍以 [API_CONTRACTS.md](API_CONTRACTS.md) 为准，后续开发须同步更新契约。

## 2. 输入与“本次优先关注项”

| 输入 | 目标用途与限制 |
| --- | --- |
| 手动观察项 | 记录用户报告的事实、数值、发生时间和来源；不因为未选择对应关注项而被忽略。 |
| CSV/JSON | 解析为逐条结构化观察；保留每条的时间、类型、单位、来源和质量信息，并与手动观察一起评估。 |
| 补充文字 | 提取用户报告的症状、行为变化、背景和疑虑，作为待核实线索；原文可追溯。文字中的数值或事件未经校验时，不得冒充设备测量值或视频所见。 |
| 历史基线 | 使用该人已有且质量合格的基线及适用时间段作对照；记录基线是否可用、学习中或已过期。不能用群体常模伪装成个人基线。 |
| 可选视频 | 提取片段内可见的动作、姿态、恢复和时间点，并保留不确定性；不从画面猜测心率、疾病、身份或片段外事件。未上传视频不阻止其他资料分析。 |

将表单中的 `What would you like reviewed?` 改为可选的 `Primary concern (optional)`／“本次优先关注项（可选）”。其语义是**用户最想先看到哪个问题的回答**：

- 默认不选择，系统检查全部受支持的风险，并按处理紧迫程度展示发现。
- 选择某一项后，系统仍处理全部输入、检查全部风险，并执行相同的决策与预警策略；只在结果中优先展示该项结论或说明该项为何无法判断。其他更紧急的发现和行动提示仍须显著可见。
- 关注项不是证据、诊断标签或规则开关，不参与过滤观察、改变风险阈值、压低其他风险或抑制预警。
- 现有关注项名称可作为初始展示选项；以后增加风险类型时，表单选项和后端可识别风险类型不必一一绑定。

至少需要一条可用的手动观察或一个可解析的结构化文件，沿用当前提交要求；视频是附加证据。若后续要允许仅凭文字或视频提交，须另行评审输入质量和预警策略。

## 3. 综合评估与决策要求

### 3.1 证据准备与融合

1. 校验输入格式、单位、人员归属、时间、来源、覆盖范围及授权；保存原始输入与标准化证据之间的关联。分析须区分观察时间、文件内各条时间、视频片段时间和历史基线时间，不能仅因资料出现在同一次提交中就认定同时发生。
2. 将手动、文件、文字和视频中的可用内容组织成带来源与质量标记的证据。比较同一时间范围内的支持、反驳和缺失信息；对明显冲突给出具体解释，例如“报告 10 分钟无活动，但对应视频中可见站立和坐下”。冲突不会自动证明任一来源真实。
3. 针对所有有证据的风险方向分别生成发现：观察到的状态或变化、与个人基线的差异、支持和反驳证据、证据覆盖范围、可信程度及未解决的问题。缺少基线时仍可描述直接观察，但不能宣称“高于/低于个人平常水平”。
4. 将各项发现汇总为本次评估状态及行动优先级；保留次要发现，不能让一个稳定指标抵消另一项独立的严重信号。对无证据或证据不足的方向使用“无法判断”，不得用“未发现异常”暗示已完成排查。模型生成的文字只解释已校验的发现，不得自行创造新证据、等级或预警。

### 3.2 状态、建议与预警

- 本次状态沿用 `Stable / Watch / Important / Critical / Unknown` 的语义；`Stable` 仅表示**本次有足够且新鲜的适用证据、未发现受支持风险**，不是对老人整体健康的保证。多项发现并存时，首页摘要体现最高的有依据处理优先级，并逐项解释其余发现。证据不足以得出可靠总体结论时为 `Unknown`，同时可对已确认的局部发现给出建议。
- 建议必须对应具体发现和不确定性，例如联系老人确认状态、核对手表佩戴与时间、补充同一时段的资料、查看已有告警或寻求专业帮助。不得从有限资料输出疾病诊断、用药或治疗指令。
- 是否创建 Alert、Alert 等级及通知行为由**与优先关注项无关**的版本化、可审计决策策略决定。每项预警记录触发的发现、采用与排除的证据、规则/模型版本、决策时间、等级、理由及建议动作。模型只能提供可核查的观察或线索，不直接决定最终等级。
- 有建议不等于必须有 Alert：对于证据有限、仅需补充资料或核对设备的情况，可以只显示建议。达到经验证的预警条件时，即使用户选择了其他关注项，也必须产生相应 Alert。低置信度、冲突或缺少关键上下文时，不得仅凭模型措辞升级为高等级预警。
- 既有告警与本次评估须避免重复创建；重试或补充资料可更新仍在处理中的结论，但不能无依据重开已结案的告警。具体去重、升级和通知条件在后续版本化策略中确定并测试。

### 3.3 模型职责、英文输出与篇幅

- 视频模型的角色定义为 **home care video evidence reviewer**：只提取片段内可见动作、姿态、相对时间点、画面限制，以及与其他资料的可核查一致或冲突之处。输出结构化证据；不得根据角色设定推断疾病、身份、生命体征或片段外的状态。
- 综合说明模型的角色定义为 **family-facing assessment explainer**：只根据已校验的观察、视频证据、个人基线和决策结果，为家属解释发现、差异、冲突、不确定性及行动建议。它不得创造测量值、风险等级、Alert 或决策理由；自由文字和视频中的指令均作为不可信资料处理。
- 两种模型的系统指令应分别说明角色、输入范围、允许的任务、禁止的推断、目标读者、输出字段与失败时的行为。先生成可校验的结构化字段，再由页面呈现；仅写“扮演医生”或“简短回答”不能替代这些约束。
- **所有面向用户的新生成 Assessment 结果必须使用英语**，包括视频观察、综合摘要、逐项发现、证据冲突、局限、建议、预警原因和回退文案。用户提交的中文或其他语言原文可在证据详情保留，并标明其为原始输入；面向用户的解释应有英文版本。语言要求只改变表达，不改变证据和决策。
- 英文首屏以易读为准：综合摘要约 **70–100 words**，每项重要发现约 **25–50 words**，下一步行动 **1–2 sentences、通常不超过 50 words**；首屏总量目标约 **150–300 words**。这是展示目标，不得为压缩篇幅省略更紧急的发现或关键不确定性；完整证据、更多发现和技术细节可展开查看。
- 输出至少包含可追溯的 evidence references、事实与推断的区别、未知项和模型使用状态。服务端验证字段、长度、证据引用及数值来源；校验失败时显示英文的受控回退说明，不把无效模型输出展示给用户。紧急告警与通知不等待模型润色。

## 4. 结果页与异常情况

结果页按家属可读的顺序呈现：

1. **本次状态与时间范围**：状态、判断时间、覆盖的观察时段和最需要处理的事项；清楚区分“分析已完成”与“状态可确定”。
2. **综合总结**：用户报告和导入了什么、视频实际看到了什么、与个人基线如何比较、各来源相互支持或冲突之处；不把上传视频等同于视频已参与分析。
3. **风险发现与行动**：每项发现的状态、主要依据、可靠性/局限和具体建议；所选优先关注项先呈现，但其他更紧急发现与行动保持醒目。
4. **预警结果**：明确显示“已产生预警／未达到预警条件／证据不足”，并展示等级、原因、关联事件及通知状态；样例工作区的告警和通知必须标为 sample/simulated。
5. **证据与技术详情**：原始观察、视频时间点、被排除或不适用的证据、模型是否成功使用、基线状态以及决策版本可追溯；原视频过期或删除后，保留符合策略的文字证据与审计记录，不假装仍可播放原片。

基线尚未建立、视频失败、资料超出适用时间范围、来源冲突或部分文件无效时，仍处理其余可靠资料，标明 `partial` 或相应局限，并指出缺少什么才能改进判断。若无可靠证据，不给出 `Stable` 或看似确定的健康结论。历史上传视频的结束不等于老人之后未恢复；不得仅因此推断当前紧急状态。

## 5. 原始差距与后续实现验收依据

| 本轮优化前的代码行为 | 目标行为 |
| --- | --- |
| `scenario` 决定 `evaluate()` 进入哪个单一规则分支，并作为事件类型；`General check` 下的其他风险可能无法成为结论。 | 用可选 `primaryConcern` 表达展示优先级；风险识别、等级和预警对该字段不变。同一提交可有多项发现。 |
| 手动项和文件观察参与规则，`note` 主要进入文字摘要；视频结果仅在有限条件下参与跌倒判断。 | 文字线索和所有有效视频观察进入有来源标记的融合流程；未经核实的文字不直接成为测量值，视频与结构化资料的冲突必须进入结论。 |
| 规则一次返回一个等级、标题和建议；结果页难以解释多个并存风险。 | 返回总体状态及逐项发现、证据关联、冲突、基线比较、建议与预警原因，并在页面完整呈现。 |
| 目前对个人基线的利用限于少数指标，缺失时常得到笼统的“不足以判断”。 | 明确标注基线可用性；在缺少基线时保留直接观察所支持的局部结论，并说明无法做的比较。 |
| 当前 API 契约要求 `scenario`，且结果字段围绕单一 `finding`。 | 后续同步调整输入/结果 schema、历史记录兼容、事件关联、审计、UI 与自动化测试；新契约发布前不把本文目标描述为已实现。 |
| 现有视频提示词以动作提取为主，文本提示词只生成单事件摘要；输出没有统一的英语与篇幅要求。 | 分别定义视频证据整理与家属评估说明的角色、结构化输出和校验；所有新生成的用户可见结果及回退文案使用英语，并按首屏篇幅目标呈现。 |

本文件定义产品行为，不在此指定具体医学阈值、模型生成的风险概率或生产通知承诺。阈值、证据权重和预警策略须另行版本化、验证和审计，不能由提示词或前端文案暗中决定。

截至 2026-10-03，样例工作区已支持可选 `primaryConcern`、逐项风险发现、英文说明、视频录制时间确认、自由文字线索摘要以及与关注项无关的样例告警决策。当前评估仅覆盖已有观察类型，个人基线比较主要涉及心率和步数；现有阈值属于样例规则，尚未经临床验证。模型的英文、结构和数值校验已加入，但跨模态事实一致性仍需代表性样本验证。真实设备、通知送达和临床用途不属于已交付能力。

## 6. 验收场景

以下场景的“预警”均指符合版本化决策策略后在样例工作区产生的样例 Alert；表中不预设未经验证的阈值。

| 场景 | 期望总结 | 建议 | 预警行为 |
| --- | --- | --- | --- |
| 未选择优先关注项，提交多类有效观察 | 汇总所有可识别风险与正常证据，说明时间范围和基线差异；按紧迫程度排序。 | 针对最需要处理的发现给出具体动作，其余发现仍可查看。 | 独立检查每项发现；达到条件的风险可触发预警。 |
| 优先关注活动，却出现另一项有充分证据的风险 | 先回答活动关注项，同时醒目展示另一项更紧急风险及依据。 | 优先呈现更紧急的行动，不让关注项掩盖它。 | 另一风险达到条件时照常触发预警。 |
| 手填异常与同一时段视频相互支持 | 说明两种来源各自看到的内容、时间对齐情况和仍未知的部分。 | 给出与证据强度相称的联系或复核动作。 | 只有满足统一策略的证据条件才触发相应等级。 |
| 手填“无活动 10 分钟”，对应视频显示站起与坐下 | 明确写出冲突，不能直接判为持续无活动或整体稳定。 | 核对时间、手表状态，并联系老人确认需要时的实际情况。 | 不凭被反驳的无活动报告单独触发高等级预警；其他独立风险仍可触发。 |
| 补充文字提出疑虑，但缺少可核实观察 | 标为用户报告的线索，说明尚不能确认具体事件或生理异常。 | 建议联系老人并补充相关时间、观察或测量资料。 | 不仅凭未经核实的文字自动产生高等级预警；如另有充分证据则按该证据决定。 |
| 个人基线尚未建立或已过期 | 描述直接观察；明确无法判断相对个人平常状态的变化。 | 提示补充近期有效资料或继续积累基线。 | 依赖基线的预警条件不成立；不依赖基线的独立强证据仍按策略处理。 |
| 上传视频但模型失败 | 明示视频未参与本次判断，保留结构化资料的部分结论。 | 依据剩余证据建议行动，并提供可行的重试/补充资料路径。 | 不使用虚构的视频证据；剩余证据达条件时仍可预警。 |
| 多项风险同时存在 | 分别列出每项风险及证据，总体状态体现最高有依据的处理优先级。 | 给出有顺序的行动，不用单一句子掩盖次要发现。 | 分别留存预警原因，并按去重策略关联事件，避免重复告警。 |
| 发现需核对的设备或资料问题，但无可靠风险证据 | 状态为无法判断或有限结论，说明资料为何不可用。 | 建议核对设备、时间或补充资料。 | 可以只有建议而无风险 Alert；不得误报为 Stable。 |
| 有充分、相互支持且满足已验证条件的风险证据 | 明确说明触发依据、等级、时间范围与不确定性。 | 给出与等级一致的及时联系或处理动作。 | 产生相应 Alert，记录版本、证据和理由；与优先关注项选择无关。 |
| 用户提交英文补充文字，视频模型输出英文或分析失败 | 保留可追溯的原文；用户可见的综合结果、视频观察或回退说明均为英语，且不改变证据含义。 | 英文建议清楚指向已验证发现和缺失资料。 | 语言与篇幅不改变预警判定；模型失败仍按可用证据决策。 |

## 7. 边界与引用

本需求面向家属提供可解释的照护风险提示，不承诺疾病诊断、治疗效果或仅凭短片确认老人当前整体健康。若未来把输出用于临床诊疗或对外声称疾病预测，需要另行评估证据、验证和适用监管要求。此边界与 [FDA《Clinical Decision Support Software》指导文件](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/clinical-decision-support-software) 对面向患者/照护者的软件功能需要独立审视的说明一致；该引用不构成对本产品监管属性的结论。
